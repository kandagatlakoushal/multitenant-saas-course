Where the tenant comes from

 Browser: GET /api/trades/9001     X-Tenant-Id: globex   (forged)
   -> Spring Security chain: session -> OidcUser -> AuthorizationFilter
   -> TenantResolutionFilter (ours, AFTER authentication)
        1. any client X-Tenant-Id?   -> 400 + security metric
        2. tenant := directory(issuer, sub)   (or an IdP-owned claim)
        3. none / unknown            -> 403
        4. set context; finally clear
   -> controller -> builder adds X-Tenant-Id: acme -> internal services
  • Get the tenant from an IdP-owned claim or a control-plane user→tenant mapping keyed by issuer and sub. Never from a user-editable profile field.
  • Users in several tenants: the tenant is a choice, checked against membership on every request.
  • Reject a client-sent header rather than strip it. Rejecting surfaces probing and old front-end code.

Azure: Map requests to tenants.

http.authorizeHttpRequests(a -> a.anyRequest().authenticated())
    .oauth2Login(Customizer.withDefaults())
    .addFilterAfter(new TenantResolutionFilter(directory), AuthorizationFilter.class);

Trap: don't make the filter a @Component. Boot registers every Filter bean with the servlet container, so it would also run before the security chain, before authentication. Either don't make it a bean, or disable its registration with FilterRegistrationBean.setEnabled(false). Spring Security: Servlet Architecture.

The lenient filter and IDOR

String t = req.getHeader("X-Tenant-Id");
if (t != null) TenantContext.set(t); else TenantContext.set(directory.tenantFor(user));   // every user is every tenant
FormExampleDefence
Tenant IDORForged header, ?tenant=, tenant in the bodyTenant only from the authenticated identity
Object IDORGET /trades/9001 owned by another tenantTenant-scoped lookups (schema or RLS). Return 404, not 403.

Both are OWASP A01 Broken Access Control (insecure direct object references, CWE-639). It recommends deny by default and logging access failures. Internal services trust X-Tenant-Id only because the browser cannot reach them.

Practice (10 min)

Today the BFF reads X-Customer from the browser "for the admin view". Write the change list before checking.

Worked answer
  • Remove X-Customer handling. Any client tenant header gets 400 and increments a security metric.
  • Add TenantResolutionFilter after authentication, not as a bean, with fail-closed 403.
  • Admin view: a separate role, switching only to tenants on that admin's allow-list, checked on every request, audited, and stored in the server-side session.
  • Outbound calls carry X-Tenant-Id from the context through the builder. The reporter is not reachable from the browser.
  • Object lookups are tenant-scoped and return 404.
