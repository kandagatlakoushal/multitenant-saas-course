Cheat sheet

The compressed essence of all lessons, one block per day. Prints on about four pages.

Day 1: Foundations and tenant identity (lessons 1–3)

WHY SHARE        cost, onboarding minutes not weeks, one release
PRICE            blast radius, leak risk, noisy neighbour, less bespoke freedom

MODEL PER LAYER  silo = dedicated | pool = shared | bridge = mix across layers
PER TENANT       tiering: big tenant -> dedicated queue / own DB
ISOLATION        enforced + tested in EVERY model; silo != isolated by magic

PLANES           control  = registry, onboarding, offboarding, per-tenant config
                 app      = ingester, parser, enricher, rules, reporter

TENANT CONTEXT   ASSIGN once at trusted edge (source queue / authenticated user)
                 PASS ON: JMS property tenantId | HTTP X-Tenant-Id (internal only)
                 HOLD: ThreadLocal, set at boundary, clear() in finally
                 FAIL CLOSED: missing/unknown -> throw -> retry -> DLQ
                 NO DEFAULT TENANT. Never re-derive from business data.

CONFIG           "Could two tenants want different values?" yes -> run-time lookup
                 frozen: @Value field, @ConfigurationProperties, @PostConstruct load,
                         @Profile per customer, static init

STARTER          AutoConfiguration.imports + @AutoConfiguration
                 @ConditionalOnProperty(havingValue=..., matchIfMissing=...)
                 legacy class: havingValue=false, matchIfMissing=true
                 new class:    havingValue=true
                 conditions work on CLASSES and @Bean METHODS only,
                 NOT on @JmsListener methods

Day 2: Data isolation (lessons 4–7)

APPROACH        DB/tenant      schema/tenant           shared tables (+RLS)
isolation       strongest      good (search_path)      weakest; RLS helps a lot
cost            high           low-med                 lowest
migrations      N DBs          N schemas (fan-out)     1 (big table)
connections     pools x pods   1 pool/server           1 pool
restore 1       easy           pg_dump -n              hard
noisy nbr       isolated*      shared server           shared everything

SEARCH_PATH     first matching schema wins; pg_catalog first; pg_temp first for tables
                MISSING SCHEMA IS SKIPPED SILENTLY -> falls through to public
                set ONLY the tenant schema; keep public empty; no CREATE on public
                SET = session (survives pool return; reverted if its tx rolls back)
                SET LOCAL = transaction only; no effect in autocommit
                use set_config('search_path', ?, false) with a registry-validated value
                temp tables live per CONNECTION -> ON COMMIT DROP / avoid
                one tenant per transaction (borrow happens once per tx)

HIKARI          connectionInitSql = once per physical connection (NOT per borrow)
                resets JDBC-API state on return, NOT SQL-level SET
                switch on EVERY borrow (DelegatingDataSource.getConnection)
                connections = pods x pools_per_server x maxPoolSize <= server limit
                leakDetectionThreshold in test/staging

ROUTING         AbstractRoutingDataSource: which DB. No default target. lenientFallback=false
                wrapper: which schema. Combine: route -> pool -> switch

LIQUIBASE       separate job, not app startup; batches; record per-tenant result
                expand -> migrate -> contract (code works on old + new)

CACHES          every cache / map / lock / counter / dedup key includes tenant
                @Cacheable default key = method params only (no tenant!)

Day 3: Messaging and context propagation (lessons 8–10)

DESTINATIONS   stage.shard-k (pool) | stage.<tenant> (silo) | one destination() fn
               virtual topic: VirtualTopic.X -> Consumer.<svc>.VirtualTopic.X
               inbound IN.<tenant>: broker authz = only that customer writes
               avoid selectors-per-tenant at scale

GROUPS         JMSXGroupID = tenantId + ":" + key   (order per key per tenant)
               order holds WITHIN ONE QUEUE only

SHARDING       Math.floorMod(id.hashCode(), N)   NOT abs(h)%N, NOT h%N
               N -> N+1 moves ~N/(N+1) tenants (one-way door)
               moving = drain old shard first, or ordering breaks
               options: consistent / jump hash; persist shard in registry
               hot shard -> promote big tenant to DEDICATED

BROADCAST      explicit scope=GLOBAL on allow-listed destinations
               fan out: per tenant set/try/finally clear, 1 tx per tenant
               "no tenant" on a normal message still = fail closed

DLQ            throw -> rollback -> redeliver (default 6, verify) -> DLQ
               ActiveMQ.DLQ shared by default; individualDeadLetterStrategy DLQ.<dest>
               dlqDeliveryFailureCause; metric DLQ depth BY TENANT
               replay: keep original tenantId, current destination, rate-limited

THREAD HOPS    @Async, executors, CompletableFuture (pass executor!),
               parallelStream (avoid), cache refresh, Reactor publishOn/subscribeOn
               fix: TaskDecorator | Micrometer ContextRegistry + ContextPropagatingTaskDecorator
                    | Reactor contextWrite + automatic propagation
               always capture -> set -> run -> clear in finally
               InheritableThreadLocal != fix; @Scheduled = boundary, loop tenants
               cache loader sets context FROM THE KEY

OUTBOUND       interceptor on the BUILDER; build every client from it
               new RestTemplate() / WebClient.create() / RestClient.create() = no header

Day 4: Edge, operations, testing (lessons 11–13)

BFF EDGE       tenant := f(authenticated identity)   claim (IdP-owned) or user->tenant map
               client X-Tenant-Id -> 400 + metric (reject > strip)
               multi-tenant user: choice CHECKED against membership every request
               filter AFTER authentication (addFilterAfter(..., AuthorizationFilter.class))
               don't @Component it (or FilterRegistrationBean.setEnabled(false))
               lenient filter (header if present) = every user is every tenant
               OWASP A01 / IDOR (CWE-639); scope every lookup; 404 not 403
               internal services: unreachable from browser, authenticated callers

NOISY NBR      quota (per period) | rate limit (per second, token bucket per tenant)
               bulkheads: listener container per shard/dedicated, executor per tier
               ingester throttling = back-pressure into the tenant's OWN source queue
               load shedding early & cheap; retries back off   [SRE-Overload]
               structural fix = tiering (dedicated queue / own DB)

OBSERVABILITY  MDC tenantId set/cleared with TenantContext (MDC is a ThreadLocal too)
               tenant tag on ~5 key metrics only; tier tag elsewhere; MeterFilter
               per-tenant alerts on errors / DLQ / lag (averages hide one tenant)

LIFECYCLE      onboard: PROVISIONING -> schema+migrate -> queues/authz -> config -> ACTIVE -> smoke
               offboard: SUSPEND -> drain -> export -> retain -> delete everything -> tombstone
               never reuse tenant IDs; backups hold data until expiry

TESTS          leak (2 tenants, same keys) | forged header | missing tenant
               concurrency (1-thread pool, alternate tenants) | missing schema
               outbound header | cache leak | ArchUnit rules | real PostgreSQL
